## Ownership and integration

Each encoder exclusively borrows Writer; each decoder borrows Reader. Plain and dictionary codecs also borrow DataType, while BinaryDecoder selects the Arrow byte-array type through its generic parameter and stores nullable. DictionaryDecoder owns an ArrayRef for already loaded values. Constructors store state without general file-bound or schema validation; DictionaryDecoder::new asserts the outer dictionary shape, and PlainDecoder::new unconditionally returns Ok. ## Binary layout and null semantics

For N rows, write the sliced payload spans in order, then N+1 absolute Int64 byte positions. Return the position-table start, not the first payload byte. The first position is Writer::tell before payloads; later array offsets are rebased to the current absolute end. The raw Int64 buffer is written without explicit endian conversion or framing. A nonempty list of empty arrays writes one endpoint; an empty input slice asserts. Exactly Utf8, Binary, LargeUtf8 and LargeBinary are supported; views return InvalidInput. (rust/lance-file/src/versions/v1/encoding/binary.rs:48-105)

The encoder ignores original validity. Decoder nullable=true marks equal adjacent positions null, so valid empty values become null and null slots retaining nonempty payload cannot be distinguished from valid values. nullable=false returns all values valid, including empty spans. This is a frozen representation rule, not a universal null-preserving binary codec. (rust/lance-file/src/versions/v1/encoding/binary.rs:61-86; rust/lance-file/src/versions/v1/encoding/binary.rs:165-232)

Range reads first fetch N+1 Int64 positions through PlainDecoder, subtract the first absolute position and cast offsets to Int32 for small byte arrays. Payload IO is skipped when start>=end; otherwise request that absolute byte range. Array construction is fallible, but negative/nonmonotone offsets and exact response size have no dedicated local checks. The internal endpoint assertion is weaker than the subsequent endpoint access. (rust/lance-file/src/versions/v1/encoding/binary.rs:153-233; rust/lance-file/src/versions/v1/encoding/binary.rs:394-415)

## Selection rules and IO cost

| Behavior | BinaryDecoder | PlainDecoder and dictionary key reads |
|---|---|---|
| Empty range beyond logical length | Reject if end exceeds length before empty check | Return empty before bounds/type checks |
| Reversed range with end in bounds | Return empty | Return empty |
| RangeFrom starting beyond length | Return empty reversed range | Return empty reversed range |
| Multiple Ranges | InvalidInput | InvalidInput |
| Empty Indices | Typed empty, no IO | Typed empty, no IO |
| Take planning | Full first-to-last position span; fixed 64KiB byte-distance threshold | Reader block size; Boolean-specific block arithmetic |
| Ordering validation | Sorted-input assumption, no sorting; null index unwraps during sizing | Raw selector values drive planning without sorting or null preflight |

Selection evidence: rust/lance-file/src/versions/v1/encoding/binary.rs:286-328; rust/lance-file/src/versions/v1/encoding/binary.rs:394-428; rust/lance-file/src/versions/v1/encoding/plain.rs:306-343; rust/lance-file/src/versions/v1/encoding/plain.rs:374-439; rust/lance-file/src/versions/v1/encoding/dictionary.rs:122-174.

Binary takes precompute the sum of selected value lengths, allocate payload and N+1 offsets, read planned chunks with ordered buffered(reader.io_parallelism), then copy a contiguous chunk once or gather each requested value. The position span can be large for two far-apart rows; a contiguous value run can exceed the nominal 64KiB threshold. Output is materialized even when the range-reader payload can share Bytes storage. (rust/lance-file/src/versions/v1/encoding/binary.rs:246-390)

Plain takes keep consecutive rows in the same chunk regardless of block_size, and otherwise split by distance from the chunk's first row. Boolean takes split on row/(block_size*8). Both read enclosing ranges, apply Arrow take and retain all decoded chunk arrays before concat. The IO threshold is not a maximum request size; zero/truncated Boolean block sizes and unchecked arithmetic remain assumptions. FixedSizeList<Boolean> range decoding can recurse, while take calls byte_width, which is unavailable for its Boolean child. (rust/lance-file/src/versions/v1/encoding/plain.rs:306-408; rust/lance-arrow/src/lib.rs:144-182)

## Repeated-leading-index discrepancy

The binary planner's condition is current==start_idx OR current-last_idx==1, where current is a relative row index and start_idx is a selector ordinal. For a nonempty value of length L and sorted indices [k,k], subtraction gives [0,0]; both iterations satisfy current==start_idx, leaving is_contiguous=true. The chunk reads/copies one value span L, but the output offsets and capacity count two values, reaching the debug assertion L==2L. Release execution reaches fallible array building with inconsistent offsets. This is an explicit source trace, not an executed reproduction. (rust/lance-file/src/versions/v1/encoding/binary.rs:251-284; rust/lance-file/src/versions/v1/encoding/binary.rs:309-388)

The dense test includes a repeated later index and checks correct output; it does not include a repeated first index. Its standalone planner uses a 1024-byte threshold, whereas decoder.take uses 64KiB. Do not generalize that passing fixture into all-duplicate correctness or assume the tested standalone plan is the actual take plan. (rust/lance-file/src/versions/v1/encoding/binary.rs:616-662)

## Plain bytes, recursive arrays and unsafe boundaries

Plain primitives write values only. Boolean inputs are joined bit by bit and None becomes false; other types use first-array byte_width and each array's offset/length to form an unsafe raw buffer slice. The configured DataType only selects FixedSizeList recursion; the primitive branch otherwise uses the actual first array type. It never validates that every later array has that type or enough bytes for the resulting span. Homogeneous valid Arrow arrays are a safety precondition: mixed narrower arrays can make the computed raw slice exceed its allocation. (rust/lance-file/src/versions/v1/encoding/plain.rs:60-152)

Fixed lists recursively write sliced child values, discarding parent and eventual primitive validity. Read reconstructs them with parent validity None; fixed binary reads UInt8 values then builds a width-based array. Signed dimensions are cast and multiplied without local validation. Null primitive payloads are whatever the input values buffer contains, except Boolean's explicit false substitution; the compatibility fixture's zero/null-key expectations do not prove every possible null backing value is zero. (rust/lance-file/src/versions/v1/encoding/plain.rs:73-152; rust/lance-file/src/versions/v1/encoding/plain.rs:252-304; rust/lance-file/src/compatibility_tests.rs:100-135)

bytes_to_array requires one value buffer. For FixedWidth, a short response is copied and zero-filled to (len+offset)*width; otherwise aligned Bytes can be retained and misaligned Bytes are copied. The resulting array has null_count0. This means truncated fixed-width input is not necessarily rejected: the active test supplies five bytes for three UInt16 values and expects the missing sixth byte to be zero. Bit-packed Boolean uses its separate buffer branch and starting bit offset. (rust/lance-file/src/versions/v1/encoding/plain.rs:174-249; rust/lance-file/src/versions/v1/encoding/plain.rs:575-592; rust/lance-arrow/src/lib.rs:1532-1596)

These codecs perform unchecked pointer/offset/capacity arithmetic and have assertions/downcasts in public-call paths. No local transaction, rollback, flush/shutdown, abort guard or cancellation cleanup appears. Buffered futures preserve order and limit polling concurrency but do not prove backend cancellation; complete IO ownership remains pending. (rust/lance-file/src/versions/v1/encoding/binary.rs:48-105; rust/lance-file/src/versions/v1/encoding/binary.rs:309-390; rust/lance-file/src/versions/v1/encoding/plain.rs:90-152; rust/lance-file/src/versions/v1/encoding/plain.rs:325-408; rust/lance-file/src/versions/v1/encoding/dictionary.rs:37-77)

## Dictionary keys and values

DictionaryEncoder supports all eight signed/unsigned integer key widths. It extracts each array's keys and writes them with PlainEncoder; no value comparison, dictionary merge/remap, value persistence or key-validity bitmap occurs. Supplying different dictionaries with the same key width therefore requires the caller to have already established compatible key meaning. The constructor's configured key type controls downcasts; unsupported types return Schema and supported types with an empty slice assert. (rust/lance-file/src/versions/v1/encoding/dictionary.rs:26-77)

DictionaryDecoder reads keys using PlainDecoder, clones the shared values Arc and calls DictionaryArray::try_new. Its declared dictionary value type is never compared with the supplied array; result value type follows that array. Keys lose stored validity through plain reconstruction, but dictionary values can independently be null. The one local test writes keys directly using PlainEncoder and never invokes DictionaryEncoder. (rust/lance-file/src/versions/v1/encoding/dictionary.rs:104-174; rust/lance-file/src/versions/v1/encoding/dictionary.rs:187-252)

The foundation's binary-like predicate includes views, but both concrete binary encode and facade decode reject them. PlainEncoder can write fixed-width numeric buffers beyond integer widths, whereas schema dictionary hydration explicitly accepts only eight integer value types or the four binary families. These are different boundaries; do not infer symmetric hydration from write dispatch. (rust/lance-file/src/versions/v1/encoding/binary.rs:91-105; rust/lance-file/src/versions/v1/encoding/plain.rs:90-115; rust/lance-arrow/src/lib.rs:144-182; rust/lance-file/src/versions/v1/encoding.rs:116-175)
