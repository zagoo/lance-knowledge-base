## Responsibility and ownership

FileReader owns a DecodeEngine plus Arc<CachedFileMetadata>, exposing synchronous metadata/statistics and asynchronous or blocking reads. ProjectedFileReader owns only the engine and can use Full or Indexed metadata. ReadProjection is the crate-private version-selected behavior seam for indexed validation, normalized length and asynchronous preparation. EncodingsIo, decoder plugins and LanceCache are shared Arcs; scheduling/decoding algorithms are delegated. There is no explicit spawning, cancellation guard or unsafe block in the production portion of this file. (rust/lance-file/src/reader.rs:392-455; rust/lance-file/src/reader.rs:1158-1409; rust/lance-file/src/reader.rs:1672-1932)

```text
FileScheduler
|-- tail + footer + GBO -> full schema + all CMO/protobuf columns
|   `-- exact finish_metadata -> FileReader / Full provider
`-- tail + footer + GBO + schema-or-known-schema + CMO
    `-- exact finish_metadata_index -> ProjectedFileReader / Indexed provider
        `-- requested column metadata: cache hits + sorted missing ranges
            `-- exact decode_column -> compacted prepared projection

requested projection -> exact ReadProjection.prepare -> selected read length
`-- row bounds -> RequestedRows + SchedulerDecoderConfig
    |-- async schedule_and_decode -> ReadBatchTask stream -> ordered buffered futures
    `-- blocking schedule_and_decode_blocking -> RecordBatchReader
```

These are the local call routes; “one submitted request” does not establish one backend IO, and task-stream lifetime is implemented by the delegated decoder. ## Metadata loading and byte layout

The initial read awaits object size and requests at most the reader's last block at priority0. Footer decoding requires40 bytes and reads LEu64 column-metadata start, CMO start and GBO start; LEu32 global-buffer/column counts; LEu16 major/minor; then four MAGIC bytes. It checks length and magic, not offset ordering or the version. The invalid-magic diagnostic prints the expected magic. Dispatch parses exact identity and can return legacy tags before decoding current metadata. (rust/lance-file/src/reader.rs:683-692; rust/lance-file/src/reader.rs:732-784; rust/lance-file/src/reader.rs:946-959)

GBO decoding may extend the tail backward, parses declared LE(position,size) pairs, invokes exact-version global validation and checked-ranges every descriptor against actual file length. At least one descriptor is required; buffer0 supplies the schema. FileDescriptor.schema is unwrapped, so a missing schema can panic. CMO entries require exact16-byte-per-column table length and checked position+length within the column-metadata region; overlapping, unsorted and zero-length entries are not explicitly rejected. Footer-order arithmetic and several Bytes slices remain unchecked. These are source-derived malformed-input concerns, not reproduced crashes. (rust/lance-file/src/reader.rs:787-945; rust/lance-file/src/reader.rs:961-988)

Full loading expands back to schema, decodes all column protobufs, and passes raw values into exact-version finish_metadata. Its accounting fields are overlapping, not disjoint sections: num_footer_bytes=file_size-schema_start; num_global_buffer_bytes=sum(descriptor.size); num_data_bytes=column_meta_start-global_sum; num_column_metadata_bytes=GBOstart-column_meta_start, including CMO. Actual file_size_bytes remains the authoritative store-reported size. The footer-byte and column-statistics field comments overstate or misdescribe these formulas. (rust/lance-file/src/reader.rs:120-167; rust/lance-file/src/reader.rs:970-1020)

Indexed loading fetches schema only when no caller-supplied (Arc<Schema>,u64 rows) is present, and fetches the exact CMO interval. Supplied schema/row count is trusted, even though GBO must still exist and pass descriptor checks. It does not decode per-column metadata at open. The initial tail may incidentally contain schema/column bytes; avoiding a dedicated fetch is not proof those bytes were never read. (rust/lance-file/src/reader.rs:1023-1107; rust/lance-file/src/reader.rs:2059-2072)

## Cache identity, retention and statistics

Reader factories prefix the supplied cache with path text. Column metadata keys then encode only the physical u32 column index under schema(lance.file.column-metadata-key,1), diagnostic type ColumnMetadata. The caller's parent namespace must supply any store/authority isolation. Injecting a new scheduler preserves cache and metadata with no identity check. FileReader::try_open itself always loads raw metadata; it does not consult a whole-file metadata cache first. (rust/lance-file/src/reader.rs:253-276; rust/lance-file/src/reader.rs:1693-1703; rust/lance-file/src/reader.rs:1968-2041; rust/lance-file/src/reader.rs:2178-2249)

Indexed prepare checks keys in projection order, sorts missing ranges by file offset, submits them together, decodes through the exact-version callback and caches each result. It restores projection order before returning. Fewer IO results cause an Internal missing-column error, extra results are ignored by zip, and earlier cache inserts survive a later error. No single-flight load or rollback occurs locally. Current LanceEncodingsIo separately checks its range-chunk result cardinality; custom EncodingsIo remains a trust boundary. (rust/lance-file/src/reader.rs:1589-1669; rust/lance-file/src/io.rs:102-147)

Only user globals fully inside the original tail window are copied into retained_global_buffers; index0 is excluded. The public global-buffer API still permits index0, validates index, returns retained bytes without IO, or submits one checked range and takes the first returned Bytes. Fallback bytes are not cached here; no response-length assertion is added. Copying retained bytes permits the larger tail allocation to drop. (rust/lance-file/src/reader.rs:710-730; rust/lance-file/src/reader.rs:1713-1743)

CachedFileMetadata deep sizing uses4*protobuf encoded length plus inline slice size, schema/normalized-info/retained-map children. Iterating only descriptor child sizes omits the file_buffers vector backing allocation. CachedColumnMetadata also adds inline protobuf slice size through the shared estimate. These are estimates, not allocation measurements. File statistics sums only page.buffer_sizes and counts pages, excluding serialized metadata, column buffers, padding, globals and footer despite the public size_bytes comment. Indexed provider statistics returns None without eager loading. (rust/lance-file/src/reader.rs:170-209; rust/lance-file/src/reader.rs:240-251; rust/lance-file/src/reader.rs:651-677; rust/lance-file/src/reader.rs:1524-1532)

## Projection and row-selection contracts

ReaderProjection pairs requested schema with physical indices. Full/indexed basic validation rejects empty roots, duplicate indices and out-of-bounds columns, but not schema/index count mismatch or type disagreement. Indexed shape eligibility recursively counts childless fields, rejects blob/packed nodes and checks total matches index count. Preference additionally requires four times selected count strictly less than total, with saturating multiplication; it is not a version-capability check. Direct projected open does not apply that selectivity threshold or fall back to full loading. (rust/lance-file/src/reader.rs:284-362; rust/lance-file/src/reader.rs:512-532; rust/lance-file/src/reader.rs:1109-1136; rust/lance-file/src/reader.rs:1534-1587; rust/lance-file/src/reader.rs:2151-2211)

The ProjectedFileReader type comment promises later projections remain within the base, but read_tasks simply uses the base as a default. It never compares a supplied projection against the base, and exact structural prepare receives only the requested projection plus whole provider. Likewise schema() and num_rows() return provider file-level values, not projected schema/normalized length. Treat base-subset enforcement as absent at this local boundary. (rust/lance-file/src/reader.rs:438-448; rust/lance-file/src/reader.rs:1705-1711; rust/lance-file/src/reader.rs:1880-1932; rust/lance-file/src/reader.rs:2255-2275; rust/lance-file/src/reader/structural.rs:393-431)

Normalized column lengths checked-sum page counts, replacing sparse page counts with first structural layer num_slots when present. verify_uniform_lengths requires complete selected roots to agree even for a short common-prefix request. Public column_num_rows instead sums raw protobuf page.length with ordinary arithmetic. Preserve these three distinct values: file descriptor row count, raw physical-column count and normalized projection length. (rust/lance-file/src/reader.rs:539-569; rust/lance-file/src/reader.rs:620-645; rust/lance-file/src/reader/structural.rs:274-357)

| Request | Local validation | Filter passed to decoder |
|---|---|---|
| Indices | Reject null; every value<selected length; no local empty/order/dedup check | Async replaces with no_filter; blocking preserves caller filter |
| Range / Ranges | end<=selected length only; no local start<=end or overlap check | Preserved |
| RangeFrom | start<selected length, so start==EOF is rejected | Preserved |
| RangeTo | end<=selected length | Preserved |
| RangeFull |0..selected length, including0..0 | Preserved |

Both paths cast/copy selections before calling decoder scheduling APIs. Multi-range helper ordinary-sums end-start; debug-enabled take/range logging indexes first/last without empty guards. Downstream may impose additional contracts, but those pending algorithms must not be inferred here. (rust/lance-file/src/reader.rs:1203-1369; rust/lance-file/src/reader.rs:1411-1474; rust/lance-file/src/reader.rs:1768-1877)

FileReaderOptions defaults to8MiB read chunks, DecoderConfig::default() and no byte target. Reader-created LanceEncodingsIo receives the chunk option; already-injected EncodingsIo is used unchanged. Row batch size and optional approximate byte target pass into SchedulerDecoderConfig without local positivity checks. Ordered buffered futures preserve task order and use caller readahead with no local nonzero check. with_io_stats replaces IO only when the scheduler supports scoped instrumentation. ## Embedded formats and diagnostics

EncodedBatchReaderExt supports external-schema mini and self-described input. Both retain complete Bytes, decode columns by exact version, derive projection, and obtain num_rows by summing the first column's page.num_rows, or0. Self-described mode discards FileDescriptor.length; neither normalizes sparse slots nor requires uniform root lengths. Mini mode does not validate GBO/schema. Direct slices can panic for bad offsets; describe_encoding can panic on malformed outer Any despite returning String. Its recognized URLs are /lance.encodings.ArrayEncoding and /lance.encodings21.PageLayout; inner decode failure becomes text. (rust/lance-file/src/reader.rs:2278-2414)
