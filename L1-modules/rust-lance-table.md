## State, errors and allocation boundaries

apply validates sticky pairing before mutation, then resets both words and derives content flags. Missing row IDs can fail after reset/deletion writes. Covered metadata is normalized from either word into both, whereas mismatched mixed/tagged-FRI bits fail. inherit validates only source paired bits and ORs8/10 into destination; it neither clears destination nor validates its other bits. ensure validates pairing before returning NotSupported for the selected unsupported word. (rust/lance-table/src/feature_flags.rs:140-254; rust/lance-table/src/feature_flags.rs:331-432)

The gates perform synchronous predicates over existing metadata and environment; apply repeatedly scans fragment lists and does not perform IO. UUID decode checks byte length16, uses a stack array, then Uuid::from_bytes; encode allocates a Vec copy. ExactSize stores a caller count without checking it; an incorrect count invalidates its size promise and can underflow on next. is_system_index recognizes only names, not payload validity. (rust/lance-table/src/feature_flags.rs:164-221; rust/lance-table/src/feature_flags.rs:256-329; rust/lance-table/src/format.rs:57-78; rust/lance-table/src/utils.rs:12-49; rust/lance-table/src/system_index.rs:21-24)

(rust/lance-table/src/format/row_ids.rs:49-126)

Core Bytes charges visible length by start pointer, so a small slice can retain a larger fetched buffer than this estimate reports; Arc counters are not charged by the generic Arc implementation. ## Fragment and manifest metadata

[Fragment L2](../L2-files/rust/lance-table/src/format/fragment.rs.md) and [Manifest L2](../L2-files/rust/lance-table/src/format/manifest.rs.md) preserve every line plus authored algorithms, error branches, ownership and test limits. DataFile owns a path, shared field/column-index arrays, exact file numbers, cached size and optional external base ID. Extra columns are allowed. Exact version decoding is a separate file_version call. (rust/lance-table/src/format/fragment.rs:28-169; rust/lance-table/src/format/fragment.rs:241-310)

Projection is version-sensitive: V1 delegates Schema::project_by_ids; other layouts zip field IDs to nonnegative column indices. Blob/packed struct is atomic by own mapped ID; ordinary structural fields retain only mapped descendants, except V2.0 raw pairs(0,3)/(2,0) preserve a mapped parent header even when all children disappeared. This prevents substituting evolved children into an old file's projection. Metadata projection does not itself materialize nulls. (rust/lance-table/src/format/fragment.rs:171-239)

Column lineage metadata must have exactly one carrier and a non-V1 decoded version under validate_row_lineage_carriers; missing carrier is Internal, duplicated carriers CorruptFile. The lookup alone returns None for absence and checks no column index. (rust/lance-table/src/format/fragment.rs:589-725; rust/lance-table/src/format/fragment.rs:800-828; rust/lance-table/src/format/manifest.rs:260-279; rust/lance-table/src/format/manifest.rs:478-502)

## Overlay-induced index staleness

[Staleness L2](../L2-files/rust/lance-table/src/format/overlay/staleness.rs.md) calculates exclusion sets using metadata only. Newer means overlay.committed_version > segment.dataset_version, not > index_version algorithm revision. Fields are segment.fields including covering dependencies. For each changed field it matches exact ID, indexed ancestor or indexed descendant using Schema ancestry; siblings alone do not match. Union only that field position's coverage. No deleted-row removal or actual flat-path query occurs here. (rust/lance-table/src/format/overlay/staleness.rs:24-103; rust/lance-table/src/format/overlay/staleness.rs:131-175; rust/lance-core/src/datatypes/schema.rs:656-671)

overlaid_fragments scans all fragments into borrowed HashMap keyed by truncating id as u32; duplicates overwrite. Missing segment.fragment_bitmap is conservatively all-covered, while Some excludes absent IDs. Fragment collector skips already-stale IDs and adds only nonempty exclusions; row collector unions nonempty offset bitmaps into existing map entries. Errors can leave earlier fragments mutated, with no rollback; map keys are trusted independently of Fragment.id. Both collectors return Result, not a complete query plan. (rust/lance-table/src/format/overlay/staleness.rs:106-176)

The version-only early return avoids schema work when all overlays are old/equal. Otherwise field-ancestry traversal may repeat and allocate inside nested loops; O(overlaid fragments) in comments is only the outer traversal bound. No sorted-order requirement, global latest-write elimination or value equality comparison changes the union. (rust/lance-table/src/format/overlay/staleness.rs:42-103; rust/lance-table/src/format/overlay/staleness.rs:114-176; rust/lance-core/src/datatypes/schema.rs:657-670)

Exact version delegation is now resolved in [lance-file](rust-lance-file.md): DataFile metadata writes V2_0 as(2,0), while standard file footer writes(0,3); both decode as V2_0. Manifest strict version string is2.0 and stable fallback/default is2.2. Capability support remains separate from identity recognition. (rust/lance-file/src/version.rs:19-27; rust/lance-file/src/version.rs:172-261; rust/lance-table/src/format/manifest.rs:764-778)

[Version L2](../L2-files/rust/lance-table/src/rowids/version.rs.md) covers public rowids::version; format reexports RowDatasetVersionMeta, RowDatasetVersionRun and RowDatasetVersionSequence. LoadedRowLineage has optional Arc row_ids/created_at/last_updated_at, and SpilledRowLineage maps u64 fragment IDs to those values for synchronous commit preparation. The declaration supplies no IO loader. (rust/lance-table/src/rowids.rs:17-24; rust/lance-table/src/format.rs:15-17; rust/lance-table/src/rowids/version.rs:25-42)

Each version run has a U64Segment span and one u64 dataset version. Readers concatenate span lengths, ignoring absolute span coordinates; local tests deliberately use overlapping coordinates. Constructors support empty, uniform and RLE-from-values forms. version_at scans runs linearly; get_version_for_row_id finds a row-ID segment position then calls it. Threshold filtering zips row IDs and versions and silently stops at the shorter sequence. No alignment validation is implicit. (rust/lance-table/src/rowids/version.rs:44-80; rust/lance-table/src/rowids/version.rs:212-313; rust/lance-table/src/rowids/version.rs:890-914)

The crate-internal cursor caches position/run length for adjacent requests. First rewind builds O(runs) starts; later nonadjacent requests use binary search plus a walk over duplicate starts. Empty spans are skipped. It appends to a caller Vec and can leave partial output/progress on bounds error; empty/reversed selections are no-ops. The cursor is not tied to a source identity or lifetime, so changing/replacing the sequence invalidates its caches. (rust/lance-table/src/rowids/version.rs:82-210)

VersionsIter differs: it advances at most one run when a run is exhausted. If that next run is empty, it still returns its version once. A length1/version7 run followed by length0/version9 therefore yields7,9; this is a control-flow deduction, not an executed test. mask removes empty spans but direct construction and decoding do not. (rust/lance-table/src/rowids/version.rs:314-390; rust/lance-table/src/rowids/version.rs:537-559)

Inline metadata shares Arc bytes; Column is a marker for hidden creation/update fields. JSON is an untagged inline byte list or column empty object. Inline decoding can fail; load_sequence(Column) is NotSupported. Protobuf arm conversions copy/move bytes without validation, and write/read sequence functions use repeated protobuf runs with nested spans. Nested codecs now establish LE arrays, LSB bitmap bytes and validated segment conversion; standalone Ranges serialization panics, so version spans with that variant cannot pass this writer. (rust/lance-table/src/rowids/serde.rs:98-338) (rust/lance-table/src/rowids/version.rs:392-559; rust/lance-table/src/rowids/version.rs:818-847)

| Helper | Count and update behavior | Failure/memory boundary |
|---|---|---|
| build_version_meta | Known positive physical rows -> uniform inline metadata; does not inspect existing version metadata | Panics if row-ID metadata missing; unknown/zero count -> None |
| Full rewrite refresh | Physical count first; otherwise inline row-ID length; column/absent ->0. Positive count overwrites all last-updated versions | Inline row-ID decode unwrap can panic; zero count preserves existing metadata |
| Partial rewrite refresh | Same count priority, but column row IDs without count error. Preserve/pad base values then patch valid offsets and RLE inline | Column versions require preload; inline decode errors silently default. O(rows) vector; excess offsets ignored; old metadata changes only at final assignment |

The table follows rust/lance-table/src/rowids/version.rs:654-815. None of these helpers checks monotonic current_version, touches created_at, changes feature flags or deletes a former column file. Complete transaction trigger/retry policy is still pending.

rechunk_version_sequences slices owned run spans by positional length into every requested chunk. allow_incomplete permits short/empty outputs on input exhaustion, but excess input is always an error, including a leftover empty run. Zero-sized requested chunks do not consume runs. It collects all chunk sizes/results and does not merge adjacent equal versions. (rust/lance-table/src/rowids/version.rs:561-652)

## HoleRuns: missing offsets with rank/select

[Runs L2](../L2-files/rust/lance-table/src/rowids/runs.rs.md) covers a pub struct inside private rowids::runs. Private fields retain span:u32, starts and present-before prefix counts; ends are reconstructed. try_new rejects unequal bounds, empty/reversed/out-of-span runs, overlap, ordering violations and adjacency. Both use partition_point and return None for out-of-range/hole values. present_ranges is lazy and double-ended. extend_values clips its ordinal end, searches once and streams base+offset gaps into an existing Vec; arithmetic is unchecked. Bitmap conversion scans whole bytes and only branches per bit at mixed edges, treating padding as present; its documented u32-length precondition is not checked. (rust/lance-table/src/rowids/runs.rs:83-215)

## Row-ID bitmaps, arrays and codec boundary

[Bitmap L2](../L2-files/rust/lance-table/src/rowids/bitmap.rs.md), [array L2](../L2-files/rust/lance-table/src/rowids/encoded_array.rs.md) and [codec L2](../L2-files/rust/lance-table/src/rowids/serde.rs.md) cover private child modules. read_row_ids/write_row_ids have a public reexport, while Bitmap and EncodedU64Array do not have public module routes. The exact signatures below distinguish local pub declarations, crate/super visibility and public trait implementations. (rust/lance-table/src/rowids.rs:17-33)

Bitmap stores Vec bytes plus logical len. Bit i uses byte i/8 and mask1<<(i%8); constructors zero padding. Direct fields/from_parts/slice/access do not enforce logical bounds. Full popcount counts every storage bit, but iteration truncates to len and can underproduce when storage is short. BitmapSlice borrows coordinates and counts edge/middle bytes; converting it back to Bitmap copies selected bits into fresh storage. (rust/lance-table/src/rowids/bitmap.rs:7-179)

EncodedU64Array owns U16/U32 base-relative offsets or U64 values. Vec conversion uses inclusive max-minus-min thresholds, preserves input order and chooses U16 even for a singleton. Range conversion materializes all values and instead uses strict range-length thresholds. Compressed slicing decodes/rebases; U64 slicing stays U64. min on nonempty deltas returns base without scanning, assuming an offset0 that decoded/direct values need not have. binary_search assumes sortedness. Borrowed/owned iterators are boxed. (rust/lance-table/src/rowids/encoded_array.rs:8-254; rust/lance-table/src/rowids/serde.rs:174-214)

The decoder checks reverse ranges, required oneofs/holes, packed widths, base+maximum offset overflow, sorted strictness/hole bounds, bitmap length/padding and total u64 length. It hand-parses only outer field1/LengthDelimited and rejects other outer fields; plain positive ranges bypass generated message allocation and feed folding. Adjacent ranges merge; overlap/out-of-order flushes instead of rejecting. Compact grouping accepts at least two ranges whose enclosing span fits u32 and gap validation succeeds; it does not compare wire cost. (rust/lance-table/src/rowids/segment.rs:245-266) (rust/lance-table/src/rowids/serde.rs:19-230; rust/lance-table/src/rowids/serde.rs:346-426)

Sequence serialization clones all segments, expands Ranges into ordinary wire Range messages, then encodes protobuf. Standalone U64Segment serialization panics for Ranges; version-run writer calls that path directly. Packed arrays are little-endian. Bitmap bytes are LSB-first in implementation/test, contradicting the MSB-first schema comment; use the implementation evidence to describe this checkout and retain the discrepancy until historical compatibility is examined. (rust/lance-table/src/rowids/serde.rs:232-344; rust/lance-table/src/rowids/serde.rs:436-451; rust/lance-table/src/rowids/version.rs:520-535; protos/rowids.proto:51-58)

## U64Segment: encoding choices and positional operations

[Segment L2](../L2-files/rust/lance-table/src/rowids/segment.rs.md) covers public rowids::segment, including U64Segment and a borrowing SegmentCursor; SegmentCursorState is crate-visible. The nearby parent comment calls structures private, but segment is declared pub. Variants expose bounds and bitmap/array/runs values without an invariant-checking constructor barrier. (rust/lance-table/src/rowids.rs:17-24; rust/lance-table/src/rowids/segment.rs:40-82; rust/lance-table/src/rowids/segment.rs:749-768)

from_slice/FromIterator collect values and scan min/max/count/nondecreasing order. Unsorted chooses Array. Sorted empty becomes Range0..0, contiguous distinct values become Range when max+1 fits, and values ending at u64MAX always use SortedArray. Other sorted values select the minimum estimated cost below, with ties favoring holes then bitmap then array. The estimate is heuristic: actual compressed array widths and protobuf overhead differ. (rust/lance-table/src/rowids/segment.rs:144-243; rust/lance-table/src/rowids/segment.rs:293-299)

| Candidate | Cost estimate | Construction |
|---|---|---|
| RangeWithHoles |24 +4 × missing slots | Scan every inclusive slot; collect/sort missing absolute values and encode array |
| RangeWithBitmap |24 +ceil(inclusive span /8) | Allocate full bitmap then scan/clear missing slots |
| SortedArray |24 +2 × value count | Encode collected values using actual U16/U32/U64 choice |

Cost arithmetic uses u128 and saturates to usizeMAX; it does not validate duplicates, cap allocations or ensure32-bit span fit. Distinctness is a documented precondition. For example sorted[0,0,2] is counted as three contiguous slots and becomes0..3; this is a source-derived counterexample, not an executed test. (rust/lance-table/src/rowids/segment.rs:97-239)

from_sorted_ranges creates Ranges for at least two intervals with u32 enclosing span and validated hole runs, without a cost threshold. Arithmetic before validation is unchecked for malformed intervals. as_ranges instead converts only bitmaps with logical length<=u32MAX when16 × (missing runs+1) is strictly smaller than bitmap byte length. It allocates HoleRuns even when rejected and has no table opt-in parameter. RowIdSequence::use_range_segments also has no gate; a narrowly inspected manifest-builder caller supplies the table config policy, with full candidate assembly now covered in the manifest-builder supplement and complete storage commit integration pending. (rust/lance-table/src/rowids/segment.rs:245-289)

| Operation | Observed contract |
|---|---|
| len/is_empty | Range span minus hole count or bitmap zero count; Ranges uses present count; arrays use length. Public malformed state can underflow or disagree with iteration |
| range | Stored bounding interval for range-backed arms, even if no values remain; sorted array endpoints; arbitrary array extrema |
| slice | Positional skip/take, silently short at EOF, retains numeric values, copies and reselects; zero request ignores offset |
| position/get | Translate value↔present ordinal; holes and Ranges use searches; bitmap position counts prefix bits, bitmap get uses select1 scan |
| contains | Hole membership scans holes linearly; sorted arrays search, arbitrary arrays scan |
| with_new_high | Consumes self, requires value above reported bound; range-backed val+1 unchecked; gaps can allocate proportional to distance |
| delete/mask | Assumed ordered existing values or ordered unique valid positions; rebuild/reselect, no Result validation |

These contracts follow rust/lance-table/src/rowids/segment.rs:301-747. The doc claim that range excludes tombstones is broader than implementation: all-zero bitmap with bounds0..8 reports Some0..=7 despite len0. mask also clears everything whenever the supplied list length equals segment length, regardless of duplicate/invalid entries. Constructor max protection does not extend to range-backed with_new_high. (rust/lance-table/src/rowids/segment.rs:330-376; rust/lance-table/src/rowids/segment.rs:520-580; rust/lance-table/src/rowids/segment.rs:694-710)

## Segment cursors and dense byte expansion

Cursor state is byte index plus count of set bits in preceding bytes. Backward requests reset only when requested ordinal precedes that count; an early return in a target byte keeps state at its beginning. Ordinary extension walks set bits; dense extension uses whole-byte or contiguous-one-run expansion when a fully selected byte has at least six set bits. Both rely on zero padding and can emit malformed padding past logical end. Requests past EOF silently truncate. (rust/lance-table/src/rowids/segment.rs:749-954)

The density advisory uses caller-supplied segment_len>=logical_len-floor(logical_len/4). It is separate from dense extension, which never checks density itself. SegmentCursor binds a shared borrow to one segment; SegmentCursorState accepts a new source on every call without resetting by identity, and nonbitmap operations leave old bitmap state intact. RowIdSequence cursor reset and density selection are now documented below; full stream ownership is now covered in the stream supplement. (rust/lance-table/src/rowids/segment.rs:346-354; rust/lance-table/src/rowids/segment.rs:749-855; rust/lance-table/src/rowids/segment.rs:925-954)

## Cursor policy and ReadBatchParams adapter

get/range cursor operations rewind on backward requests, cache each segment length and reset SegmentCursorState when advancing. Reusing a cursor with changed/different sequence can retain wrong cached lengths/counters. Dense policy applies only to a single bitmap segment and seeds its computed cardinality; multi-segment sequences use sparse mode. Range selection preallocates requested cardinality even when EOF clips output. (rust/lance-table/src/rowids.rs:67-170; rust/lance-table/src/rowids.rs:538-591)

## ID masks, set conversion and rechunking

mask_to_offset_ranges returns ordered half-open ordinals grouped within each segment; adjacent groups across segment boundaries stay separate. Plain ranges walk tree-map runs. Holes remove missing IDs, sort decoded holes and subtract earlier-hole count. Bitmaps use finite allow IDs when allowed cardinality<=summed bitmap span: a single bitmap filters the iterator, multiple bitmaps cache sorted IDs once and binary-search subranges. Other masks fall back to a full-span set/bitmap scan. Ranges inserts present gaps and translates rank; arrays test mask membership in stored order. (rust/lance-table/src/rowids.rs:609-798)

The bitmap helper popcounts only intervals between selected present IDs, retaining the prior position so the next interval includes that selected bit. RowAddrMask cannot carry both allow and block lists simultaneously. The dependency row_addrs allocates a Vec of iterators even on the streaming path, so no-copy of all IDs is not zero allocation. (rust/lance-table/src/rowids.rs:843-863; rust/lance-select/src/mask.rs:24-79; rust/lance-select/src/mask.rs:497-515)

Set conversion unions independently built segment sets so one bitmap's holes cannot erase IDs belonging to another overlapping segment. Order and multiplicity disappear. Contextual dependency inspection exposes two edge cases: empty Range0..0 inserts0 through saturating excluded-end conversion, and mask's plain-range run-end expression mishandles a low32 carry for odd high32 values. These are source-derived, unexecuted counterexamples requiring dedicated regressions before any fix. (rust/lance-table/src/rowids.rs:621-646; rust/lance-table/src/rowids.rs:865-905; rust/lance-select/src/mask.rs:545-588; rust/lance-select/src/mask.rs:819-828; rust/lance-select/src/mask.rs:1032-1037)

rechunk_sequences returns one sequence per requested size, consuming owned inputs. It slices/re-encodes even whole segments, so range input can materialize every row; it is not a metadata-only split. allow_incomplete permits short/empty outputs but not excess input. Empty input segments are skipped only while filling a positive remaining count; a trailing empty after the final full chunk still triggers too-many error. (rust/lance-table/src/rowids.rs:959-1052; rust/lance-table/src/rowids/segment.rs:378-387)

The narrowly read manifest helper gates use_range_segments through config key lance.row_ids.range_segments and str_is_truthy. It skips prior opted-in inline data by fragment ID and byte-start pointer, decodes other inline sequences and rewrites only if conversion changed; column metadata is skipped. The reviewed truthy helper accepts ASCII-case-insensitive 1/true/on/yes/y without trimming; other strings return false. Full manifest preparation is now covered in the manifest-builder supplement; local commit publication is covered in its supplements; full Dataset integration and released-fixture compatibility evidence remain pending. (rust/lance-table/src/transaction/manifest_build.rs:74-123; rust/lance-core/src/utils/parse.rs:4-11)

## Transaction row-ID allocation and creation lineage

[Complete row-version L2](../L2-files/rust/lance-table/src/transaction/row_version.rs.md) covers1,461 lines. The private transaction::row_version module exposes has_writer_placed_lineage through the public transaction facade; resolve_update_version_metadata and the two Transaction methods are pub(super), usable within transaction. All are synchronous and operate on supplied metadata/preloads. No store, feature gate, lock, retry or atomic commit appears in this file. (rust/lance-table/src/transaction.rs:29-54; rust/lance-table/src/transaction/row_version.rs:12-19; rust/lance-table/src/transaction/row_version.rs:73-96; rust/lance-table/src/transaction/row_version.rs:298-405)

| New-fragment metadata | Creation behavior | Last-update behavior / validation |
|---|---|---|
| Creation Column, any row-ID state | Retain marker without decoding | build_version_meta(new_version); positive count without row-ID metadata can panic |
| Row-ID Column + creation Inline | Preserve supplied creation bytes | Decode and require creation count==physical_rows.unwrap_or(0); stamp new_version |
| Row-ID Column + no creation | Error | NotSupported |
| Row-ID Inline + creation Inline/None | Decode row IDs; recompute every creation value | Found source -> cached version or1; absent source -> new_version; debug-only count check |
| No row IDs or inline decode failure, with no creation Column | Uniform creation via build_version_meta | Uniform last update; malformed row-ID bytes remain unchanged; absent IDs with positive count can panic |

The table follows ordered match arms at rust/lance-table/src/transaction/row_version.rs:206-295 and delegated count/panic behavior at rust/lance-table/src/rowids/version.rs:655-678. Creation Column overrides other classification. Zero/unknown rows clear latest metadata to None through build_version_meta, while valid empty inline row IDs produce Some(empty creation sequence). These are local contracts; builder preparation can exclude malformed combinations.

Source discovery materializes distinct needed IDs in HashSet, sorts existing-fragment references by ID, and scans row sequences whose inclusive bounds overlap. Inline row-ID corruption is ignored; Column rows require preload even before bounds can be checked. First matching source in ascending fragment order wins, including soft-deleted older copies because deletion vectors are not consulted. No early exit occurs after all IDs are found. (rust/lance-table/src/transaction/row_version.rs:97-171)

Creation sequences are decoded once per chosen source with unique fragment IDs; Column preload is cloned into owned sequences, and missing preload errors before output mutation. Missing or corrupt inline creation metadata gives fallback1 on found rows. Every row then performs a linear version_at scan over runs; the cache saves decoding but does not create a row-to-version array. Output creation versions do materialize one u64 per row before run compression and protobuf serialization. Duplicate fragment IDs can invalidate the exactly-once assumption and overwrite cache entries. (rust/lance-table/src/transaction/row_version.rs:173-205; rust/lance-table/src/transaction/row_version.rs:258-288; rust/lance-table/src/rowids/version.rs:230-254; rust/lance-table/src/rowids/version.rs:272-282)

assign_row_ids requires physical_rows for every fragment. Column or complete Inline count is left unchanged; excess Inline count is Internal. A partial Inline prefix is decoded twice, expanded, followed by fresh consecutive IDs, rebuilt and serialized; absent metadata uses a direct Range without per-row expansion. next_row_id additions are unchecked and assume a collision-free counter. The helper updates fragments and counter incrementally and does not roll back after a later error. (rust/lance-table/src/transaction/row_version.rs:332-405)

collect_pure_rewrite_row_update_frags_ids is a cardinality filter: absent row metadata is excluded, Column always qualifies and Inline qualifies if decoded length equals physical count. It does not inspect source membership. Narrow builder context establishes assign -> resolve -> cardinality filter/index registration -> assign again for Update, and uniform stamping after assignment for Append/Overwrite. The filter therefore cannot independently distinguish already filled INSERT rows. Local index effects, operation validation and full candidate-builder ordering are now covered; complete dataset integration remains pending and no runtime defect is asserted from this ordering alone.
