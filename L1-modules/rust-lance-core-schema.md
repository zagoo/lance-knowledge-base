## Construction and validation

Public `Schema` stores `fields: Vec<Field>` and `metadata: HashMap<String,String>`. Arrow import converts each Field, copies metadata, assigns missing IDs, runs `validate`, then `verify_primary_key`. A borrowed Schema conversion simply clones, while Arrow export converts fields and copies metadata without validation. Public member mutation can therefore create states not accepted by Arrow import. (rust/lance-core/src/datatypes/schema.rs:28-35; rust/lance-core/src/datatypes/schema.rs:937-976)

`validate` rejects dotted/duplicate top-level names, unapproved negative IDs, duplicate IDs anywhere and nonpositive fixed-size-list dimensions. Only matching top-level lineage names/IDs establish the reserved-ID exceptions; their datatype/nullability is not checked here. It does not check parent IDs, nested name uniqueness or primary keys. Dimension validation recursively follows nested FixedSizeList types because primitive nested lists collapse into a single Field leaf; the surrounding Field traversal handles other containers. Malformed Field reconstruction can still panic before these checks return an error. (rust/lance-core/src/datatypes/schema.rs:117-138; rust/lance-core/src/datatypes/schema.rs:351-406; rust/lance-core/src/datatypes/field.rs:170-195)

Primary-key verification requires a leaf, non-null ancestry and no List/LargeList/Map ancestry. It does not enforce data uniqueness, position uniqueness/contiguity or explicitly reject a primitive-element FixedSizeList leaf. Clustering keys have no corresponding structural verifier here and may be nullable, as tested. Positive primary-key positions sort before legacy position0; the positive u32 position is cast to i32 in its sort key, so very large positions do not sort in ordinary u32 order. Clustering positions sort directly as u32. (rust/lance-core/src/datatypes/schema.rs:140-176; rust/lance-core/src/datatypes/schema.rs:883-919; rust/lance-core/src/datatypes/schema.rs:3304-3387)

`set_field_id` starts after the greater of current and supplied persisted maxima, assigns negative IDs only, and rebuilds parent IDs. It does not guard integer overflow. Dataset callers should provide `Manifest::max_field_id` to avoid reusing dropped IDs. `merge` resets incoming IDs but leaves new fields unassigned until an explicit later assignment. `extend` appends converted fields before checking duplicate names; an Internal error leaves the mutation in place. Neither operation runs full validation. (rust/lance-core/src/datatypes/schema.rs:686-814; rust/lance-core/src/datatypes/schema.rs:2526-2569)

## Lookup and field-path grammar

`FieldRef::ById` verifies existence and produces InvalidInput on absence; `ByPath` produces FieldNotFound with suggestion candidates. Schema ID lookup includes roots, unlike Field ID lookup. Ancestry lookup ignores stored parent IDs and traverses the actual tree in reverse sibling order using cloned path vectors. `field_paths` joins ancestry names with raw dots for diagnostics; use `field_path` or `field_path_minimal` when escaping matters. (rust/lance-core/src/datatypes/schema.rs:37-84; rust/lance-core/src/datatypes/schema.rs:440-459; rust/lance-core/src/datatypes/schema.rs:629-684; rust/lance-core/src/datatypes/schema.rs:816-881)

`parse_field_path` uses backticks, doubles embedded backticks, separates unquoted dots and rejects empty/malformed segments. Double quotes, spaces and brackets are ordinary characters; earlier resolver doc examples using double quotes are inconsistent with this parser. `resolve` hides parse errors as None. Case-insensitive lookup prefers exact matches, then the first ASCII-folded match; ambiguity is not rejected. (rust/lance-core/src/datatypes/schema.rs:228-261; rust/lance-core/src/datatypes/schema.rs:566-610; rust/lance-core/src/datatypes/schema.rs:1615-1711)

| Formatter | Exact rule | Limits |
|---|---|---|
| format_field_path | Quote any segment containing a non-alphanumeric/non-underscore character; Unicode alphanumeric is accepted | Does not separately handle leading digits, SQL reserved words or empty segments; rust/lance-core/src/datatypes/schema.rs:1713-1739 |
| format_field_path_minimal | Quote only literal dots/backticks; double embedded backticks | Roundtrip promise assumes nonempty valid segments; rust/lance-core/src/datatypes/schema.rs:1741-1783 |
| escape_field_path_for_project | Preserve exact wildcard `*`; otherwise parse and quote every segment | Parse failure becomes one literal segment instead of an error; rust/lance-core/src/datatypes/schema.rs:1785-1806 |

## Comparison and schema set operations

`Schema::PartialEq` ignores schema metadata but compares Field representations. Configurable comparison optionally includes schema metadata and delegates Field policy. Default field comparison is equal length plus ordered zip; allowing nullable omissions, arbitrary subschema or ignored order switches to name maps. Extras are always rejected. Missing expected fields are accepted only under the selected omission policy; order remains checked unless explicitly ignored. Duplicate names can produce different results across fast/slow comparison and explanation paths because one maps the last actual name while the explanation chooses the first. (rust/lance-core/src/datatypes/schema.rs:178-219; rust/lance-core/src/datatypes/schema.rs:922-926; rust/lance-core/src/datatypes/schema.rs:978-1124)

Schema `project` follows requested root order and merges repeated root selections. Missing roots error or drop according to wrapper, while missing nested paths can inherit Field's empty-child success. System columns are dropped by ordinary projection and appended by the preserving variant; that variant includes rowoffset. `project_by_schema` rejects requested root names containing dots, follows the requested schema order and delegates type matching. `intersection` follows Other root order and propagates root errors; Field child intersection follows Self order and can discard errors. `merge` preserves Self field order/metadata precedence and appends new roots. These APIs do not all apply BlobHandling or atomic selection. (rust/lance-core/src/datatypes/schema.rs:263-349; rust/lance-core/src/datatypes/schema.rs:408-430; rust/lance-core/src/datatypes/schema.rs:493-548; rust/lance-core/src/datatypes/schema.rs:778-814; rust/lance-core/src/datatypes/field.rs:959-984)

## Projection selection model

`Projectable: Debug + Send + Sync` exposes a borrowed Schema. Projection owns an Arc of that trait, public HashSet<i32> IDs, four metadata flags (rowid, rowaddr, last-update, creation-version) and BlobHandling. There is no rowoffset flag. Empty uses no selections and default BlobsDescriptions; full unions a clone of the base schema. Selection methods consume/return Self. Debug omits the base. (rust/lance-core/src/datatypes/schema.rs:1147-1178; rust/lance-core/src/datatypes/schema.rs:1239-1315)

`union_column` resolves a path, inserts all ancestors and descendants of the target, and recognizes four exact raw system strings separately. Predicate methods insert/remove only matching IDs, without maintaining tree closure. Set union/intersection/subtraction operate directly on IDs/flags and retain Self's base/blob mode without checking that bases match. `union_schema` and `subtract_schema` do not enforce the base-membership checks promised in their docs: nonnegative IDs are inserted/removed directly; only unexpected negative IDs trigger debug assertions. (rust/lance-core/src/datatypes/schema.rs:1317-1545)

`to_bare_schema` applies Field projection in base order. `to_schema` then appends metadata fields in fixed rowid/rowaddr/last-update/creation order through `extend(...).unwrap()`, so duplicate existing names can panic and appended IDs remain unassigned. `into_schema`, `into_schema_ref` and `to_arrow_schema` delegate that materialization. This is schema construction, not scan execution or IO. (rust/lance-core/src/datatypes/schema.rs:1547-1612)

## Blob policy and a local discrepancy

`returns_description` exposes the private unload predicate; this is documented for early/late materialization heuristics. AllBinary loads marked blobs. BlobsDescriptions unloads marked blobs. AllDescriptions chooses every binary-like or blob field. The two set modes retain selected IDs as binary, with SomeBlobsBinary limited to marked blobs. IDs are cast from i32 to u32 for these sets. (rust/lance-core/src/datatypes/schema.rs:1158-1214)

`unload_if_needed` first loads a chosen blob via `binary_blob_mut`, otherwise unloads via `unloaded_mut`, otherwise recurses into children. For an ordinary non-blob binary field, AllDescriptions can return true from `returns_description` while `unloaded_mut` leaves the field unchanged. This follows the two reviewed functions; caller or reader behavior beyond this local discrepancy still requires investigation. (rust/lance-core/src/datatypes/schema.rs:1192-1236; rust/lance-core/src/datatypes/field.rs:648-658)
