## Concrete V2_0 ownership and initialization

Writer owns its own object writer, optional schema/type cache, field encoders, physical column metadata/mapping, per-field and aggregate row counts, global descriptors, schema metadata, boxed ArrayFieldEncodingStrategy, options and spill state. It does not compose the shared structural pipeline. Public Writer is reexported from its exact-version parent; the footer helper is effectively internal and reached through parent embedded-batch functions. (rust/lance-file/src/versions/v2_0/writer.rs:153-218; rust/lance-file/src/versions/v2_0/mod.rs:21-32; rust/lance-file/src/versions/v2_0/writer.rs:852-856)

```text
V2_0 Writer
|-- ArrayFieldEncodingStrategy -> BatchEncoder -> FieldEncoder list
|-- schema + expected types + schema metadata
|-- physical column metadata + field mapping
|-- per-field counts -> aggregate maximum/logical length
|-- ObjectWriter + user global-buffer descriptors
'-- optional spill: Pending(store,path) -> Active(sidecar,chunk index)
```

Eager construction creates lazy state then initializes. Lazy construction stores inputs and allocates the default strategy without validation or IO. Initialization validates explicit options, computes cache/page limits, validates schema and constructs BatchEncoder before installing encoders/metadata/mapping. It divides a supplied total cache budget by top-level field count; with an empty schema this can divide by zero before schema validation. Defaults are 8 MiB per root field, 32 MiB max page, keep_original_array=false and alignment64. An explicit max-page value wins over the environment; malformed environment text warns and defaults, missing/non-Unicode text silently defaults, and an environment value of zero bypasses the explicit Some(0) rejection. (rust/lance-file/src/versions/v2_0/writer.rs:184-218; rust/lance-file/src/versions/v2_0/writer.rs:326-369; rust/lance-file/src/writer.rs:56-65)

## Preparation and row mutation

write_batch initializes from its first Arrow schema, checks ExpectedTypes, selects every required field by name and prepares every field array before testing for an empty batch or the single-batch u32 limit. Missing fields fail even for empty batches. FieldEncoder::prepare_array defaults to identity and documents preparation before state mutation; concrete validation/transformation remains encoder-defined. No separate recursive nullability walk appears in this writer. The structural pipeline instead performs its own logical-nullability validation. (rust/lance-file/src/versions/v2_0/writer.rs:313-324; rust/lance-file/src/versions/v2_0/writer.rs:371-400; rust/lance-file/src/versions/v2_0/writer.rs:451-476; rust/lance-encoding/src/encoder.rs:175-183; rust/lance-file/src/writer/structural.rs:598-627)

Encoding snapshots each field's old row number, calls maybe_encode, writes out-of-line buffers, then checks aggregate u64 overflow. Counters advance before ordered page tasks and flush finish, so later failure does not rewind them. Batch counters use original batch.num_rows while encoding uses prepared array lengths; the caller/encoder relationship must preserve these lengths. write_column checks schema/index/input size/type, prepares one array, returns if that prepared array is empty, then advances only that field by its prepared length with unchecked addition and updates the aggregate maximum. A previously initialized lazy writer satisfies its schema check despite the explicit-schema wording in the error. Unequal root-field lengths are allowed. (rust/lance-file/src/versions/v2_0/writer.rs:402-506; rust/lance-file/src/versions/v2_0/writer.rs:507-584)

FuturesOrdered emits task results in insertion order; pages are written sequentially, followed by writer flush. The first error stops the loop and drops remaining local futures. The code comment describes flush as observing failed uploads without waiting for all in-flight uploads; backend implementation, spawned-work cancellation and durability are still outside this scope. (rust/lance-file/src/versions/v2_0/writer.rs:279-300)

## Buffer placement, spill and completion

Ordinary page, batch-external, global and column buffers get trailing 0x48 padding based on their payload length to64. Their starts are not repaired. V2_0 write_external_buffer writes completely raw at current position, unlike the structural sink's leading-zero alignment. Page metadata records raw lengths and wraps either page-description family in Any/Direct without checking the exact V2_0 grammar. (rust/lance-file/src/versions/v2_0/writer.rs:41-41; rust/lance-file/src/versions/v2_0/writer.rs:231-262; rust/lance-file/src/versions/v2_0/writer.rs:703-708; rust/lance-file/src/versions/v2_0/writer.rs:831-849; rust/lance-file/src/writer/structural.rs:352-360)

Spill threshold per column is max(256 KiB/max(column_count,1),64). One message can overshoot; buffers retain capacity and chunk descriptors grow. Pending is removed before awaited sidecar creation, after page payload IO. A failed creation loses pending state. Finish removes metadata/spill state, shuts down and reopens the sidecar, reconstructs all pages for each column and replaces that column's prior page vector. Late spill can therefore discard descriptions retained before activation. Cleanup is explicitly caller-owned and no local deletion occurs. (rust/lance-file/src/versions/v2_0/writer.rs:48-146; rust/lance-file/src/versions/v2_0/writer.rs:219-228; rust/lance-file/src/versions/v2_0/writer.rs:263-275; rust/lance-file/src/versions/v2_0/writer.rs:597-630)

finish flushes encoders, consumes/finishes them if present, writes descriptor and user-global table entries, column metadata, column offset table, global offset table, footer, then awaits shutdown. Descriptor and column metadata are raw protobuf bytes; each offset-table entry is a 16-byte LE(position,length) pair. Schema metadata is drained and blobs unloaded before descriptor IO. External-metadata initialization bypasses validation and replaces schema/metadata/aggregate rows without rebuilding encoder, type-cache, mapping or field-count state. It can support footer-only external output, but subsequent ordinary writes require coherent state the initializer does not establish. (rust/lance-file/src/versions/v2_0/writer.rs:586-709; rust/lance-file/src/versions/v2_0/writer.rs:768-829)

Two position assumptions need preservation: finish_writers writes out-of-line buffers raw while the planner advances virtual positions by payload plus padding; column-buffer offsets advance by payload length while actual writes include padding. Multiple unaligned buffers can violate those assumptions. These are source deductions, not evidence that current encoder producers emit such shapes. The final physical-column count mismatch panics unconditionally. No finished flag or rollback protects repeat calls; abort is an empty async body and does not drop the writer. (rust/lance-file/src/versions/v2_0/writer.rs:711-759; rust/lance-file/src/versions/v2_0/writer.rs:831-834; rust/lance-encoding/src/encoder.rs:130-159)

## Exact footer identity

| Footer-relative bytes | Standard V2_0 | Embedded V2_0 |
|---|---|---|
| 0–7 | column metadata start, LEu64 | same meaning |
| 8–15 | column offset table start, LEu64 | same meaning |
| 16–23 | global offset table start, LEu64 | same meaning |
| 24–27 | global-buffer count, LEu32 | zero in mini; one in self-described |
| 28–31 | physical-column count, LEu32 | page_table length |
| 32–33 | major0, LEu16 | major2, LEu16 |
| 34–35 | minor3, LEu16 | minor0, LEu16 |
| 36–39 | LANC | LANC |

These literal branches are independent implementations. The version decoder accepts both as V2_0, and tests distinguish standard and embedded mappings. concat_lance_footer copies input bytes and given page/column descriptors, optionally appends a cloned core schema without blob unloading, then metadata/tables/footer. It ignores ColumnInfo.index and top_level_columns and does not validate supplied buffer positions or grammar. (rust/lance-file/src/versions/v2_0/writer.rs:812-828; rust/lance-file/src/versions/v2_0/writer.rs:852-952; rust/lance-file/src/version.rs:226-262; rust/lance-file/src/compatibility_tests.rs:379-448)

## Change boundaries

Changes to standard V2_0 finish and embedded serialization must preserve their different footer identities and must account for their separate buffer/metadata paths. Preparation ordering matters for validation before maybe_encode; row and page failure paths are not transactional. Extend the existing compatibility suite with independently generated stable baseline cases when compatibility is the concern; unstable V2_3 prior revisions carry no fixture obligation here. Full encoder/backend/Dataset callers and remaining V2 binary fixtures must still be analyzed before this is a complete implementation recipe.
