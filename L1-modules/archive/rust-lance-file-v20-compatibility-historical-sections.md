## Compatibility fixture and test oracles

The deterministic input has 4,097 rows and five fields: Int32 IDs, nullable UTF8 names (every7th null), nullable Int32 lists (every11th null, every5th second child null), nullable Int8/UTF8 dictionary keys (every13th null), and nonnull LargeBinary payloads in a nullable blob-marked field. Compression metadata disables name and dictionary-value compression. Standard writers receive five batches of up to1,024 rows; embedded V2_0 uses only id/name for the first257 rows. (rust/lance-file/src/compatibility_tests.rs:36-98; rust/lance-file/src/compatibility_tests.rs:232-315; rust/lance-file/src/compatibility_tests.rs:401-408)

Stable cases compare complete current bytes to baseline includes, assert exact footer identity and read the baseline through the current reader. Read assertions include at least one multi-page physical column, full row count/schema equality and ordered value/null equality. Blob comparison ignores physical bytes under nulls. V2_3 instead writes twice in the same revision and checks equal bytes plus roundtrip; it has no checked historical fixture. The V1 test explicitly expects null lists as empty, null child integers as zero and null dictionary keys as green. The full V1 reader and writer are now independently traced in their supplements; this test still establishes only the stated fixture oracle. (rust/lance-file/src/compatibility_tests.rs:100-230; rust/lance-file/src/compatibility_tests.rs:318-524)

FsFixture exposes a local store, temp path and testing scheduler. write_lance_file collects the entire input, adds foo=bar to writer schema, finishes and returns original schema/data/mapping. read_lance_file requires that metadata, reads RangeFull with batch1024/readahead16 and collects all output. count_lance_file fully decodes/collects then sums rows. All use unwrap/assert rather than a fallible public result. The original returned schema does not receive the writer's added metadata. test_cache creates a fresh128MiB cache. (rust/lance-file/src/testing.rs:22-123)

## Provenance and generator failure boundaries

README pins baseline commit `3a72f8a61e14613f517dded6816d4bfc77817c93`, lists six SHA-256 values and requires using baseline writers for independent evidence. Local Git metadata confirms that commit exists; the six hashes match the inventory snapshot. No regeneration has been performed. The [V1 fixture](rust-lance-file-binary-fixtures.md) is now fully interpreted; both [embedded V2_0 fixtures](rust-lance-file-embedded-fixtures.md) are also fully interpreted, and the standard V2_2 binary payload is now fully interpreted. The pin identifies a commit and is not, by itself, proof of a released-package fixture. (rust/lance-file/test_data/exact_versions/README.md:3-41)

The Python script checks exact HEAD and initial clean status, copies the Rust example into the baseline, then runs two separate Cargo processes with separate outputs and one shared isolated target directory. It supplies no --locked/--offline/profile flag. Cleanup removes the copied source and newly created examples directory in finally, but copying occurs before that guard; cleanup errors can mask the build error. It does not restore arbitrary build modifications or check final source cleanliness. (rust/lance-file/test_data/exact_versions/datagen.py:23-62; rust/lance-file/test_data/exact_versions/datagen.py:86-108)

For each filename, compare both generated byte arrays, then either compare the checked fixture or immediately replace it with --write. A later mismatch can leave earlier fixtures replaced; publication is not atomic across the set. The printed hash is computed from first-run bytes and never compared against the README table. The Rust generator intentionally uses historical APIs, including previous::writer and version fields removed from current option structures; it should not be adapted to the code under test merely to make it compile there. (rust/lance-file/test_data/exact_versions/datagen.py:109-129; rust/lance-file/test_data/exact_versions/datagen.rs:12-35; rust/lance-file/test_data/exact_versions/datagen.rs:102-228)
