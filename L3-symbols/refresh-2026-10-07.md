## Manifest transaction compatibility

- **T01.** The transaction offset now uses field 23. Field 21 is retained as `transaction_section_deprecated`; readers prefer 23 and fall back to 21, while current writers leave 21 unset. This offset is metadata rather than a prerequisite for opening a dataset version. `protos/table.proto:194-211`; `rust/lance-table/src/format/manifest.rs:1102-1105,1184-1185`.
- **T02.** An absent/unknown transaction operation decodes to `Operation::Unknown`. Encoding and manifest application reject Unknown, and JNI conversion rejects it too. A future operation can therefore remain readable as unknown history without becoming a valid new local write. `rust/lance-table/src/transaction/operation.rs:256-261`; `rust/lance-table/src/transaction/proto.rs:404-406,709-715`; `rust/lance-table/src/transaction/manifest_build.rs:773-779`; `java/lance-jni/src/transaction.rs:1222-1224`.
- **T03.** Do not infer universal conflict rejection from the Unknown documentation. Constructing our own Unknown fails, and ordinary operation-specific checks add incompatible branches, but our Clone returns success directly and UpdateBases retains a permissive wildcard. This is a source-level limitation of the broad comment, not a promise that every operation conflicts with unknown history. `rust/lance/src/io/commit/conflict_resolver.rs:458-463,638-704,2466-2512`.
- **T04.** If transaction serialization fails while checking an ambiguous commit outcome, the result remains Unknown; associated files must be preserved rather than assuming the commit failed. `rust/lance/src/io/commit.rs:288-290`.

## Managed blob identity, encoding and publication

- **B01.** Blob kinds 4/5 are Managed/ManagedWithBase. Managed resolves relative to the owning descriptor file's table base; ManagedWithBase uses the exact explicit base ID, including 0 and the maximum u32. Their known zero size denotes empty content, unlike the external unknown-size convention. `rust/lance-core/src/datatypes.rs:617-644`.
- **B02.** Managed URIs must be nonempty canonical relative paths: no leading/trailing slash, `://` separator, backslash, empty segment, dot or parent segment. Position plus size must not overflow. Both logical encoding and concatenation validate this contract. `rust/lance-core/src/utils/blob.rs:8-30`; `rust/lance-encoding/src/encodings/logical/blob.rs:340-364`; `rust/lance-file/src/concat.rs:440-452`.
- **B03.** The MANAGED_BLOBS feature is bit 14; bit 15 is the first unknown feature boundary (not an enabled transaction feature). Managed blob activation is a paired reader/writer flag and remains sticky. Publication enables it when a newly published physical file contains a Blob V2 field; metadata-only changes do not independently activate it. `rust/lance-table/src/feature_flags.rs:98-107,125-126,387-401`; `rust/lance-table/src/transaction/manifest_build.rs:1750-1778`.
- **B04.** Current V2.2/V2.3 blob writers use managed bases. Managed-part writes spill every nonempty inline payload into independent `_blobs/<uuid>.blob` objects. Managed part reservations still require disjoint blob ID ranges although descriptors encode bases instead of those IDs. Cleanup of a staging target does not imply removal of independent managed objects; ordinary GC and checkpoint coordination apply. `rust/lance/src/dataset/write.rs:119-134,202-205,2462-2467`; `rust/lance/src/dataset/blob.rs:807-835`.
- **B05.** Prepared ManagedWithBase inputs must name a registered base. Reading resolves an explicit descriptor base first, otherwise the owning data file's base; range reads use known offset/size. Object-store reuse requires compatible base URI and no credential override. `rust/lance/src/dataset/blob.rs:1105-1131,4994-5038,5179-5195`; `rust/lance/src/dataset.rs:2470-2498`.
- **B06.** Descriptor traversal supports structs and list/large-list nesting and rejects unsupported containers. Preservation retains existing Managed descriptors, adopts legacy packed/dedicated objects without copying their payload, leaves External descriptors unchanged, and copies inline payload when required. Compaction enables the managed-preservation mode for V2.2/V2.3. `rust/lance/src/dataset/blob.rs:5201-5279,5357-5437`; `rust/lance/src/dataset/optimize.rs:2596-2602`.
- **B07.** Base ID allocation finds a free ID, not a reserved sentinel. UpdateBases excludes zero from new allocation and prevents replacing an existing explicit base when managed blobs are enabled. `rust/lance-table/src/format/manifest.rs:682-699`; `rust/lance-table/src/transaction/manifest_build.rs:1985-2001`.

## Clone and garbage collection

- **C01.** Clone destination preflight permits only a missing dataset/object; authentication or other storage failures propagate. Tagged FRI is no longer a blanket prohibition on Dataset clone: the clone paths relocate its references. The old standalone guard remains a legacy API. `rust/lance/src/dataset.rs:3345-3395,3464-3473`; `rust/lance-table/src/system_index/frag_reuse/metadata.rs:52-70`.
- **C02.** Deep managed-blob clone deduplicates `(base ID, URI)` references. Local references retain their relative path; explicit-base objects receive fresh destination paths and rewritten descriptors with local Managed kind. Offset and size remain unchanged. Only blob-containing columns are rewritten, preserving other fragment files. [Focused Key File](../L2-files/rust/lance/src/dataset/blob/clone.rs.md). `rust/lance/src/dataset/blob/clone.rs:30-128,132-259`; `rust/lance/src/io/commit.rs:604-626`.
- **C03.** FRI clone preserves transition wire bytes while patching base references; deep clone localizes bases, shallow clone redirects local references to a newly registered ancestor base and retains existing explicit bases. It refuses unsupported ledgers before copying, creates a fresh index entry, and preserves spilled files after an ambiguous publication outcome. Foreign external-detail bases currently open with default store parameters; per-base credentials are not propagated through this clone path. `rust/lance/src/index/frag_reuse.rs:2185-2320,2335-2415`; `rust/lance/src/io/commit.rs:223-233,427-629,709-749`.
- **C04.** Cleanup scans managed descriptors and retained FRI references. Failure to read a retained manifest aborts; absent expired data loses deletion proof. Unsupported/unresolvable FRI history disables `_fri` collection conservatively. Retained/branch references protect objects, and only proven expired references or sufficiently old unverified orphans are collectible. Foreign-base ownership is respected; this is not permission to collect arbitrary external stores. `rust/lance/src/dataset/cleanup.rs:735-742,822-914,1226-1258,1313-1338,1648-1789,1857-1888`.

## Fragment reuse, remapping and concurrency

- **F01.** A lifted v0 record retains its legacy dataset version; native tagged records do not have that watermark. Unknown envelopes are tolerated for ordinary inspection but block maintenance that cannot preserve their meaning. CreateIndex with tagged trim is tightly validated, and user-index-only changes may pass admission. `rust/lance-table/src/system_index/frag_reuse/ledger.rs:63-94,191-205,241-252`; `rust/lance-table/src/system_index/frag_reuse/gate.rs:85-140,191-201`.
- **F02.** A rewrite group without a transition must not overlap an index's known coverage; missing coverage also refuses it. Mixed transition-carrying rewrites apply this rule to each bare group. Stable-row-ID deferred compaction is permitted only when no row-ID-domain user index requires remapping; this does not remove the separate prohibition on tagged transition intent for stable-row-ID datasets. `rust/lance-table/src/system_index/frag_reuse/gate.rs:231-256,350-367`; `rust/lance/src/index/frag_reuse.rs:1476-1545`; `rust/lance/src/dataset/optimize.rs:2358-2386`.
- **F03.** Batch remapping may report stored fragment physical-row counts and a default 256 MiB materialization budget. The fallback checks all stored fragments, including retired ones, estimates allocation before allocating, validates output length, and omits identity entries. Only typed RemapUnavailable permits maintenance to skip; corruption and unrelated failures propagate. `rust/lance-index-core/src/remapping.rs:37-50,92-145,167-218`.
- **F04.** RowAddrTranslator supports synchronous and batch sources. Per-unit resolution deduplicates addresses; ScalarIndex retains its original remap API and supplies a streaming default with a bounded materialization fallback. Plugin `load_index` and `load_index_with_remapping` receive the persisted segment version, not just the plugin's newest version. `rust/lance-index-core/src/remapping.rs:259-262,334-362`; `rust/lance-index-core/src/scalar.rs:666-723`; `rust/lance-index/src/scalar/registry.rs:169-209`.
- **F05.** Tagged remap planning follows ordered compaction and stable-partition lineage. Fully covered sources translate to destinations. Partial compaction before stable partition can withdraw coverage; partial stable-partition paths or missing required lineage block the segment. Legacy lifted watermarks can reverse already-folded coverage before replay. The old compaction-only comment is narrower than the actual planner. `rust/lance/src/dataset/optimize/remapping.rs:486-604,626-672`.
- **F06.** Maintenance intersects planned coverage with reader-derived servable coverage, accounts for newer overlays, and preserves original segments on typed remap unavailability or Drop. Successful remap publishes fresh metadata; a no-hop case keeps existing files/base. Unsupported history is refused rather than guessed. `rust/lance/src/dataset/optimize/remapping.rs:864-1100`.
- **F07.** Pruning considers derived live coverage and keeps unusable/unknown-coverage segments rather than allowing them to mask useful siblings. Trimming retains provenance from recorded segment bitmaps plus forward dependencies; a missing bitmap warns and cannot pin tagged records; retained wire bytes are preserved. Unknown envelopes prevent trim. `rust/lance/src/dataset/index/frag_reuse.rs:355-450,650-895`.
- **F08.** Tagged trim and redundant-segment pruning rederive their result against the latest manifest on retry. A no-op receives a specific conflict marker handled by cleanup. Legacy v0 rebasing accepts the current ordered subsequence produced by trim but refuses unrelated history replacement; the base UUID remains fixed across attempts. `rust/lance/src/io/commit/conflict_resolver.rs:124-160,2840-2910,3078-3147`.
- **F09.** Same-name staged index maintenance may replay only with compatible fields/type. Stable-ID/FRI rewrites retry on concurrently introduced row-ID-domain indices. Commit preparation decodes FRI only when physical columns were actually rewritten, allowing append/add-column paths to carry opaque history. `rust/lance/src/io/commit/conflict_resolver.rs:1170-1186,1716-1740`; `rust/lance/src/io/commit.rs:1595-1616`.

## Scalar/vector extension changes

- **I01.** Bitmap now supports merging multiple segments together with new data and one old-data filter per segment. It rejects empty input, filter-count mismatch and mismatched value types; filters retaining nothing avoid old bitmap reads. The old merge function is deprecated and delegates with no new data/no filters. `rust/lance-index/src/scalar/bitmap.rs:706-772,2244-2280`.
- **I02.** New JSON indices accept scalar values only; inferred arrays/objects and explicit LargeBinary target parameters are rejected. Legacy parameter representation remains. The JSON wrapper still lacks its target's persisted version, so loading passes the target plugin's current version as a documented stand-in; do not claim complete nested-version persistence. `rust/lance-index/src/scalar/json.rs:607-616,936-945,1103-1130`.
- **I03.** IVF flat cosine transformation retains the normalized L2 metric for partition assignment. IVF-RQ rejects Hamming before training. Shuffle scatter validates null/out-of-range partition IDs and omits empty ranges; duplicate columns and worker failures produce errors rather than unchecked assumptions. `rust/lance-index/src/vector/ivf.rs:177-184`; `rust/lance/src/index/vector.rs:1222-1229`; `rust/lance-index/src/vector/v3/shuffler.rs:607-652,893-913,1190-1194`; `rust/lance/src/index/vector/builder.rs:1024-1035,1063-1065`.

## Query and public API changes

- **Q01.** Scanner schema projection is public. It resolves matching names/types rather than requiring identical field IDs; incompatible or absent fields fail. Row-ID-only projection no longer adds a row-offset column unnecessarily. `rust/lance/src/dataset/scanner.rs:1864-1867`; `rust/lance-datafusion/src/projection.rs:311-315,351-355`.
- **Q02.** Boolean coercion applies to AND/OR/NOT, preserving nullable/list semantics for null checks and comparisons. Aggregate lowering preserves aliases and output schema naming. These are Lance adapter contracts; upstream DataFusion internals were not analyzed. `rust/lance-datafusion/src/logical_expr.rs:217-231`; `rust/lance/src/dataset/scanner.rs:3144-3174`.
- **Q03.** Count pushdown crosses only single-child cardinality-preserving nodes without a fetch limit. Retaining deleted rows requires physical rather than visible row counts; range scans or unavailable writer metadata retain unknown statistics instead of asserting an exact count. `rust/lance/src/io/exec/count_pushdown.rs:394-423`; `rust/lance/src/io/exec/filtered_read.rs:2902-2909,3535-3552`; `rust/lance/src/io/exec/scan.rs:817-837`.
- **Q04.** Python create_index warns with DeprecationWarning when deprecated `index_cache_size` is supplied; it is ignored in favor of the byte-based dataset/session cache. `write_fragments(enable_stable_row_ids=...)` does not allocate IDs: assignment happens at commit. `python/python/lance/dataset.py:4044-4053,4444-4447`; `python/python/lance/fragment.py:1312-1317`.

## Trust boundaries

Existing completed crates are not reanalyzed. Frozen bodies and the 9,717-record catalog remain historical snapshots; dated overlays provide current coordinates and contract amendments. Java and peripherals remain mapped only. Ordinary changed files retain Module Map coverage. The new clone helper is a selected Key File, not evidence of deep coverage of every clone backend.
