## Indexed counting and public APIs

- **A01.** Dataset::count_indexed_rows rejects empty index/filter strings; fragment IDs must be unique and current. Supplying physical segment UUIDs requires a nonempty unique list, matching index name, usable scalar details, a keyed field, and nonempty current fragment coverage. `rust/lance/src/dataset/scanner.rs:1447-1563`.
- **A02.** Selected segment coverage must include every same-name contributing segment with an overlapping recorded bitmap. An explicitly supplied fragment set must equal that coverage. Without UUID selection, same-name segments are selected and an optional validated fragment scope is retained. Missing sibling bitmaps are skipped by the contributor checker; do not invent a stronger proof for unknown coverage. `rust/lance/src/dataset/scanner.rs:1564-1656`.
- **A03.** Count uses Scanner filtering, empty data projection plus internal row ID, and restricted scalar-index planning. If the filter produces no index query, planning fails rather than silently choosing a table scan. UUID restrictions propagate to scalar execution/materialization nodes. This does not promise that all residual evaluation or deletion handling is index-only. `rust/lance/src/dataset/scanner.rs:1603-1621,3444-3456,3489-3496,4171-4181,7494-7505`.
- **A04.** Fast search uses row IDs internally but no longer automatically exposes `_rowid` in the output projection. `rust/lance/src/dataset/scanner.rs:2567-2576`.
- **A05.** Java adds the four-argument countIndexedRows overload with UUID selection; the three-argument API remains. Validation/forwarding is documented as mapped-only binding coverage, with Rust owning count semantics. `java/src/main/java/org/lance/Dataset.java:1485-1559`.
- **A06.** Python get_version returns the checked-out version, timestamp and manifest summary without storage reads according to its facade contract; it calls PyO3 current_version, which wraps Dataset::version. Existing versions() shares the timestamp converter. Conversion retains local datetime.fromtimestamp behavior and microsecond precision; it is not a timezone-aware nanosecond timestamp. `python/python/lance/dataset.py:3165-3194,6135-6143`; `python/src/dataset.rs:924-934,2141-2153`.

## Top-k query materialization

- **Q01.** TopKLateMaterialization is a public physical optimizer that recognizes SortExec with fetch, or a fetched SortPreservingMerge over partition-preserving fetched SortExec. It narrows the read to sort columns plus row ID, performs top-k, takes remaining columns, and restores original column order/schema. It must be registered by its caller; this record does not claim global default registration. `rust/lance/src/io/exec/topk_late_materialization.rs:77-95,136-267`.
- **Q02.** The rule declines retained-deletion reads, mismatched dataset URI/version in dropped takes, ineligible reads and limits that keep every row when an upper bound is known. Unsupported shapes retain the original plan with a debug reason. `rust/lance/src/io/exec/topk_late_materialization.rs:165-213,326-351,432-446`.
- **Q03.** Built-in pass-through nodes are pure column projections without aliases, non-hash repartition, coalesce and cooperative nodes. A custom node requires explicit certification, one child, unchanged fields, equal cardinality and no fetch; certification additionally promises unchanged values and no stored column indices. Metadata-changing custom nodes are reapplied above take. `rust/lance/src/io/exec/topk_late_materialization.rs:122-134,255-265,270-322,355-385`.
- **Q04.** TakeExec preserves input ordering/equivalences only if input fields are unchanged at the leading output positions. Extending a struct can invalidate that claim; then new equivalence properties are used and maintains_input_order is false. `rust/lance/src/io/exec/take.rs:574-590,610-623,697-701`.
- **Q05.** Expression coercion recursively applies a column type only to literal-only arithmetic/shift/string-concatenation expressions. Other expressions are left for DataFusion coercion, avoiding premature narrowing of inner-column arithmetic. Upstream implementation is outside scope. `rust/lance-datafusion/src/logical_expr.rs:74-90,128-142`.

## JSON schema and scalar lifecycle

- **S01.** The schema adds JsonTargetDataType values unspecified=0, boolean=1, int64=2, float64=3, utf8=4, deprecated large-binary=5, and JsonIndexDetails.target_data_type field 3. Its specified preservation rule copies every nonzero raw enum value through a non-retraining rewrite, including unknown values; unspecified may be replaced only by authoritative recovery, not inferred guesses. Target format version is still not recorded. `protos/index.proto:250-325`.
- **S02.** **Implementation gap at this pin:** current JSON wrap/update/train constructors explicitly write Unspecified. The proto's intended recorded-type preservation behavior is not yet implemented by these paths. Do not infer persisted type recovery or unknown-enum preservation from the schema declaration alone. This is a verified distinction, not a KB verification failure. `rust/lance-index/src/scalar/json.rs:108-115,196-203,1040-1046`; `protos/index.proto:274-282,309-324`.
- **S03.** Preprocessed training data now carries TrainingCriteria. The public builder declares value order plus row IDs, and scalar training compares declared versus required criteria, returning InvalidInput on mismatch. It is no longer guarded solely by a BTree-only assertion; canonical bitmap fragment builds still reject preprocessed data. `rust/lance/src/index/create.rs:140-157,445-455`; `rust/lance/src/index/scalar.rs:405-417`; `rust/lance-index-core/src/scalar.rs:494-497`.
- **S04.** Bitmap cache state now writes bounded lookup batches (32 MiB target, with a larger single key allowed), and its cache codec version is 2. Label-list cache version also becomes 2 because it embeds that state. These are cache-body versions, not a claim that persisted scalar index formats changed to version 2. `rust/lance-index/src/scalar/bitmap.rs:87-90,295-327,362-399`; `rust/lance-index/src/scalar/label_list.rs:892-896`.
- **S05.** MultiMatchQuery serializes every leaf under match_queries; legacy query/columns/boost keys are added only when all leaves have columns. Deserialization prefers the nonempty new leaf list and otherwise uses the legacy shape; old readers may lose per-leaf settings. `rust/lance-index/src/scalar/inverted/query.rs:557-627`.

## MemWAL schema ownership and reads

- **W01.** ShardWriter::evolve_to loads the current base table schema with field IDs and its maintained index configs, then calls evolve_schema. MemWAL must be initialized. `rust/lance/src/dataset/mem_wal/api.rs:857-926`.
- **W02.** Schema replacement runs under the writer state lock, rejects WAL-only mode and changed primary-key field IDs, and returns None for equivalent schemas. An empty active memtable is replaced within its generation; a nonempty one rotates, retaining its old schema. A changed schema returns a SealFence that can have no sealed generation. `rust/lance/src/dataset/mem_wal/write.rs:3895-3999`.
- **W03.** WriterSchema separates caller logical schema, stored field-ID/tombstone/nullable representation, and prepared blob descriptors. Writes are shaped under the same lock as their destination schema. Input names are checked by position and RecordBatch construction validates the logical layout before durable admission. `rust/lance/src/dataset/mem_wal/write.rs:1867-1903,1991-2013,2123-2179`.
- **W04.** WAL entries can carry generation metadata, absent in WAL-only mode. Replay can flush a nonempty memtable when an entry advances the generation; entries lacking it retain the size-rule route. This is not a promise that arbitrary older WAL schema changes are reconstructible. `rust/lance/src/dataset/mem_wal/wal.rs:44-62,1117-1125`; `rust/lance/src/dataset/mem_wal/write.rs:1522-1550`.
- **W05.** GenerationRead maps current names to stored names by field IDs, with distinct physical and full-text paths for list nesting. When the table has no IDs, it falls back to shared names. Missing primary-key mapping errors. Both live memtables and flushed generations use this reconciliation boundary. `rust/lance/src/dataset/mem_wal/scanner/generation_read.rs:84-158,410-448`.
- **W06.** Base-table alteration rejects primary-key renaming while MemWAL is attached, alongside existing retype/nullability-tightening restrictions. Cached key names make a rename unsafe for writers that have not refreshed. `rust/lance/src/dataset/schema_evolution.rs:491-531,851-874`.

## Updater and cleanup

- **U01.** Updater requires each next() batch to be updated before advancing. finish() rejects an outstanding batch or unread input; its lookahead retains a discovered batch so the caller can continue. Failure during update leaves restoration state unspecified: discard and restart that updater. Do not confuse this with the explicitly recoverable early-finish probe. `rust/lance/src/dataset/updater.rs:183-210,272-289,386-415`.
- **U02.** Modern-file deletion restoration emits bounded blank-only chunks and keeps a compact reusable source row. Legacy row groups cannot defer blanks across batches. On finish, a trusted writer-version/physical-row count is checked against restored rows; old untrusted metadata retains weaker checks. The new blanks module chooses format/type-aware filler values without defining a new persisted grammar. `rust/lance/src/dataset/updater.rs:314-383,416-460,572-600,759-796`; `rust/lance/src/dataset/updater/blanks.rs:24-65,293-354,458-499`.
- **C01.** Cleanup deduplicates managed descriptor scans by store/base namespace, fragment serialization, projected fields/IDs and retained state. A OnceCell stores completed scan outcome; per-fragment scans run sequentially within a manifest to bound buffers. Missing expired descriptors may be skipped; retained failures still abort and failed scans are not cached as complete. `rust/lance/src/dataset/cleanup.rs:313-339,594-681`.
- **C02.** Delete rate limiting is shared across the parent cleanup and all cascaded branches, overriding branch-specific rates. Each request takes a permit before delete; None leaves the whole cascade unthrottled. The limiter is not installed for non-deleting inspection. `rust/lance/src/dataset/cleanup.rs:467-479,1073-1085,1584-1595,1920-1928,1962-1967`.
- **C03.** Managed-reference helpers now take a caller-supplied Scanner. Clone passes source.scan(); cleanup passes fragment.scan(). The descriptor identity and blob copy/rewrite contract remains unchanged. `rust/lance/src/dataset/blob/clone.rs:227-244`; `rust/lance/src/dataset/cleanup.rs:645-648`.

## Vector training maps

- **V01.** count_trainable_vectors is a threshold probe: nonnullable non-multivector columns return total rows; nullable/multivector paths use bounded readahead and stop after enough usable vectors, excluding null rows and null list elements. It need not return the complete population count. `rust/lance/src/index/vector.rs:529-578`.
- **V02.** Streaming coreset training dispatches L2/Cosine to the L2 policy, Dot to its policy, and Hamming to HammingCoresetAlgorithm. The separate float-policy selector rejects Hamming. The new float/Hamming adapters and compact counters are mapped implementation details; no recall or performance result is claimed. `rust/lance/src/index/vector/ivf.rs:3837-3877,5033-5058`.
- **V03.** K-means convergence uses absolute loss scale and a separate zero-loss case; cluster radii begin at negative infinity so negative distances are represented, then empty clusters become zero. `rust/lance-index/src/vector/kmeans.rs:333-339,369-387,1149-1161`.
