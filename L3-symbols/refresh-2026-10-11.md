## F01 — Field-ID activation

Manifest field 24 is an optional non-reusable field-ID high-water mark. It must agree with writer bit 15; the reader bit is invalid. Dropped IDs remain reserved. An overwrite receives fresh IDs above the previous high-water mark. The unknown-feature boundary is now bit 16.

`protos/table.proto:167-174,281-292`; `rust/lance-table/src/feature_flags.rs:102-114,405-427`; `rust/lance-table/src/format/manifest.rs:478-522`.

## F02 — Migration and restore

Dataset::migrate_to_non_reusable_field_ids is one-way and idempotent, repairs the pre-activation schema and executes its activation commit with zero retries. Clients must honor writer feature flags; the migration cannot enforce that client policy. Once active, restoring a pre-activation version is rejected; allowed restores preserve the larger current high-water mark.

`rust/lance/src/dataset.rs:3300-3343`; `rust/lance-table/src/transaction/manifest_build.rs:190-204`.

## F03 — Checked allocation

Field::try_set_id uses an i64 candidate and checked i32 conversion. Schema::try_set_field_id preserves assigned IDs and allocates after both maxima; try_reassign_field_ids clears existing IDs first. Discard partially updated schemas on allocation error. Schema projection uses a name index at 32 requested columns, preserving the first duplicate name.

## T01 — Conversion and retry identities

Resolve raw Arrow IDs at the language conversion boundary, before core commit allocation. Merge resolves names/types, Project can preserve explicit rename identities but cannot allocate new data-less identities, and ambiguous raw/canonical file mappings are rejected. Each commit attempt clones and canonicalizes its transaction against the latest high-water mark and read-version schema, preventing a provisional ID from binding to a concurrent new field.

## T02 — Transition validation

A successor cannot lose or decrease an active high-water mark. Newly referenced IDs must belong to its canonical schema; every overwrite reference must belong to the replacement schema. Existing identities cannot move parents or change logical type. Detached Merge is allowed only with unchanged schema; detached Project/Overwrite/Restore are rejected after activation. ## E01 — Unstable 2.3 grammar

SparseLayout no longer stores the old num_buffers/num_items/num_visible_items/has_large_chunk fields. Structural layers are field 2, sizes derive from the page and layers, and sparse positions/counts use generic unsigned block encodings. Range and Delta are compression variants 14 and 15 for unstable 2.3. Do not preserve the superseded unstable layout as a compatibility contract.

## E02 — Stable version isolation

Stable v2.1/v2.2 readers require Flat variable offsets and reject Range/Delta. Only the v2.3 compression strategy opts into generic variable-offset miniblocks; its validator distinguishes optional-payload blocks, buffer-backed blocks, miniblocks and per-value positions. A shared proto file does not make new 2.3 grammar legal in stable formats.

## E03 — Typed bounded sequences

Generic sequences use unsigned 32/64-bit values. Empty sequences require Constant without a scalar. Range has positive step and checked final value; Delta requires at least two values and a bounded concrete child. Composite RLE/dictionary/delta/general cannot recursively introduce arbitrary composites. General wraps plain Flat; dictionary indices and RLE run lengths are u32.

`rust/lance-encoding/src/compression.rs:1375-1754`; `rust/lance-encoding/src/encodings/physical/sequence/decoder.rs:33-117`.

## E04 — Selection and framing

SequenceBlockCodec verifies a common descriptor and unchanged payload arity for each chunk. Selection rejects mixed empty/nonempty families, chooses common Constant/Range before comparing other candidates, and ranks candidates by serialized bytes, transform depth, CPU rank and stable rank. Generic binary offsets are used only when their serialized cost beats legacy framing; readers validate buffer counts, zero start, monotonic offsets and exact final byte length.

`rust/lance-encoding/src/encodings/physical/sequence.rs:78-277`; `rust/lance-encoding/src/encodings/physical/binary.rs:446-508,594-698`.
