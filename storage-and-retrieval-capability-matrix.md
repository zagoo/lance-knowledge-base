## Layer and status definitions

- **Lance File:** physical columnar data storage, encoding, metadata, column projection, and reads by row range or row position. Lance files can also hold index data. This does not make a standalone data-file reader a complete business-query engine.
- **Dataset:** the Lance Dataset/Scanner layer and its supporting query and index modules. It selects indices, executes predicates and search operators, handles fragments and row visibility, combines results, and fetches requested columns.
- **External/application:** embedding models, application-managed traversal, distributed worker scheduling and workflow orchestration, or separately installed ecosystem projects such as Lance Graph. Native worker and commit APIs do not themselves provide a cluster service.
- **Fetch rows:** retrieve original data columns using row identifiers or resolved physical row addresses returned by an index.
- **Implemented:** the pinned source has the relevant implementation and calling path. Unless explicitly stated otherwise, no feature-wide experimental label was identified in the reviewed evidence. This is not an assertion that every API, index format, language binding, or released package is stable.
- **Conditional:** implemented subject to a build feature, file-format version, or another stated requirement. Conditional support is not automatically experimental support.
- **Storage/access only:** the representation can be stored and read, but the corresponding general-purpose retrieval algorithm is not supplied automatically.
- **Experimental/incubating:** explicitly designated as such by the cited source or project classification.

The layer boundaries follow the knowledge base's [architecture and read path](L0-orientation.md) and [index lifecycle and query contracts](L3-symbols/protocol-index.md).

| **Whole-field text equality** | String columns | File + **Dataset** | String equality; BTREE/BITMAP can accelerate it | Evaluate `text = literal` through an index or scan → return rows satisfying equality | **Implemented** | Distinct from BM25, phrase search, and substring search. It does not require an FTS index. See [BTree equality lookup][S02]. |
| **Substring search through NGRAM** | Strings | File + **Dataset** | **NGRAM**, normally character trigrams | Extract query grams → intersect posting sets → fetch candidate text → evaluate the original `contains` predicate | **Implemented** | Posting intersections are candidates, not proof of a complete substring match. | **Regular-expression search** | Strings | File + **Dataset** | Regex evaluation; **NGRAM** acceleration for suitable patterns | Extract usable gram constraints from the regex → obtain candidates → evaluate the regex against original text | **Implemented** | Not every regex can use an index. Patterns without useful gram constraints can require a scan. Current FM-Index code does not provide this route. See [text query routing][S12]. |
| **Substring search through FM-Index** | Text; training also accepts supported binary arrays | File + **Dataset** | **FM-Index**, based on the **Burrows-Wheeler Transform (BWT)** | Backward-search the pattern in each relevant segment → locate occurrences → map them to rows → union segment results | **Implemented**; no explicit feature-wide experimental designation identified | Current query code supports the substring path and explicitly rejects regex queries, despite broader wording in the format document. | **Array/tag-list membership** | Supported `List`/`LargeList` columns, such as lists of labels | File + **Dataset** | **LABEL_LIST**, backed by a bitmap index | Look up one label's row set; union sets for ANY; intersect sets for ALL → fetch matching rows | **Implemented** | Accelerates supported membership predicates such as `array_has`, `array_has_any`, and `array_has_all`. | **Nested-record and Map access** | `Struct`, List, Map, and supported combinations | **File stores structure**; Dataset performs projection and applicable expression evaluation | Column projection, field/element access, and predicates; no universal nested-structure index | Resolve the access expression → read relevant columns → access fields/elements → evaluate predicates | **Implemented with type and expression constraints** | Storage support does not imply specialized index support for every nested expression. | **JSON document and path queries** | `lance.json`/JSONB semi-structured documents | File stores the extension representation; **Dataset queries it** | JSON functions; **JSON path wrapper** around a target scalar index such as BTREE/BITMAP | Extract the indexed path into typed values during construction → match a compatible query accessor/path → search the target index → return rows | **Implemented** | One index targets a specified path, not every field in the document. Matching typed `json_get_*` accessors can be routed; `json_extract` is deliberately not routed through this index. See [JSON index contract][S17] and [routing code][S18]. |
| **Blob and multimedia payload access** | Images, audio, video, model artifacts, and other binary payloads | **File/Blob storage + Dataset APIs**; content understanding is **external** | Blob descriptors, object/range addressing, full or lazy payload reads; no automatic media-content index | Find a row through metadata or another search index → resolve its Blob descriptor → read the complete payload or requested byte ranges | **Implemented**; Blob v2 is **conditional on file format 2.2 or newer** | Storing media does not automatically produce semantic embeddings or content search. ## Cross-cutting interpretation

1. **Index files are not the same as an independently searchable data file.** Dataset normally handles index selection, fragment coverage, deletion visibility, residual predicates, result merging, and fetching original columns. An index itself being serialized as Lance files does not move those responsibilities into `LanceFileReader`.
2. **Persistent indices usually require explicit construction.** Supported query paths can account for uncovered appended data and stale index entries with supplementary reads. Explicit vector/full-text `fast_search` trades away uncovered-data completeness. ANN recall remains a separate source of approximation even when all fragments are accounted for. See the [query contracts](L3-symbols/protocol-index.md) and [vector planner][S06].
3. **A candidate-producing index can still support an exact final predicate result.** NGRAM, RTree, ZoneMap, and Bloom-filter paths can return supersets; the execution layer must perform the required rechecks. Do not confuse these false-positive candidate sets with the recall tradeoffs of ANN or LSH. See the [SearchResult certainty contract](L3-symbols/protocol-index.md).
4. **BM25 and inverted retrieval describe different parts of one search path.** Posting lists locate matching documents; BM25 assigns lexical relevance scores. Neither automatically performs embedding-based semantic matching.
5. **Arrow extension types are not necessarily external projects.** JSON, Blob, and image/tensor representations can be handled by Lance's own SDK/core facilities. In contrast, embedding generation and Lance Graph are separate layers.
6. **File-format stability, index-format stability, API stability, and production qualification are independent.** At this source pin, file format **2.2 is the stable/default selection**, while **2.3 is unstable/next**. The ordinary capabilities listed above do not all require 2.3. See the [version policy implementation][S28] and [knowledge-base format matrix](L3-symbols/format-spec.md).
7. **Native distributed operations and a native clustered service are different capabilities.** Lance supplies the actual fragment writes, index artifact construction, supported segment merges, and dataset/index publication. The external caller or integration supplies worker launch, task assignment, completion tracking, worker retries, metadata collection, and the decision to publish. The distributed-write guide identifies separately maintained Ray and Spark integrations; these do not make those runtimes or a cluster-service control plane part of the core Lance library. Dataset commit retries are native transaction behavior, not a distributed job scheduler. See the [write guide][S29], [commit API][S31], and [indexing responsibility boundary][S32].

## Explicit experimental and incubation markers

- **MinHash LSH:** explicitly experimental; index files and details may change incompatibly and require an index rebuild. [Source][S23]
- **FTS `block_size=256`:** explicitly experimental. This is a configuration-specific marker, not a classification of the entire BM25/FTS capability. [Source][S08]
- **Lance Graph:** listed under incubating subprojects in the pinned core repository's community documentation. This classification is snapshot-specific; the external repository evolves independently. [Source][S27]
- **Lance file format 2.3:** explicitly unstable/next. File format 2.2 is the stable selection at the assessed revision. [Source][S28]
- **Advanced Python `IndicesBuilder` helper:** its methods are explicitly experimental. This marker applies to that helper, not automatically to `create_index_uncommitted`, `merge_existing_index_segments`, or `commit_existing_index_segments`. [Helper designation][S35]; [public segment-build API][S33]
- **Fragment-write progress hook:** the `progress` parameter of `write_fragments` is explicitly experimental. The designation does not classify the entire distributed-write protocol as experimental. [Source][S30]
- **Other rows:** an implementation or the absence of a reviewed experimental marker is not a substitute for a formal stability commitment or workload-specific validation.
